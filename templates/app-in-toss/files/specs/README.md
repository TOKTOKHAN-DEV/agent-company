# specs — 기능 명세

**화면을 만들기 전에 여기부터 씁니다.** 이 회사의 하드 룰입니다.

명세 없이 구현으로 넘어가면 `pnpm preflight` 가 잡습니다. 수용 기준이 없는 명세도 error 입니다.

```
specs/
├── README.md        이 파일
├── _template.md     복사해서 시작하세요 (밑줄로 시작하면 검사 대상에서 제외)
└── <기능>.md        실제 명세
```

## 왜 명세가 먼저인가

토스 미니앱은 **심사를 통과해야 나갑니다.** 심사 항목의 절반은 기능이 아니라 동작 규약입니다 —
뒤로가기가 첫 화면에서 미니앱을 닫는가, 바텀시트가 진입하자마자 뜨지는 않는가, 권한이 거부돼도
기능이 도는가. 이런 건 화면을 다 만든 뒤에 고치면 구조를 갈아엎어야 합니다.

수용 기준에 미리 적어 두면 `ui-builder` 가 그걸 보고 만듭니다.

## 쓰는 법

```bash
cp specs/_template.md specs/포인트-적립.md
pnpm agent spec-writer "포인트 적립 화면"
```

`pnpm preflight` 가 각 명세에서 확인하는 것:

| 섹션 | 필수 | 없으면 |
| --- | --- | --- |
| `## 수용 기준` | 필수 | error — 제출 불가 |
| `## 화면` | 권장 | warn |
