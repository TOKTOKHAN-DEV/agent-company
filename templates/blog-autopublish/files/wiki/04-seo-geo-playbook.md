# 04 — SEO / GEO 플레이북

## 두 개의 다른 게임

| | SEO | GEO |
| --- | --- | --- |
| 대상 | 검색 엔진 (Google, Naver) | 답변 엔진 (ChatGPT, Claude, Perplexity, AI Overviews) |
| 목표 | **순위** | **인용** |
| 핵심 신호 | 타이틀, 메타, 링크, 속도 | 추출 가능한 구조, 명시적 Q&A, 출처, 엔티티 |
| 성공 지표 | 유입 클릭 | 답변에 이름이 나오는 빈도 |

같은 글이 둘 다 노려야 하므로 프론트매터에 `seo`와 `geo` 블록이 분리되어 있습니다.

## SEO 체크리스트

- [ ] `seo.title` ≤ 60자. 비우면 `title`을 씁니다.
- [ ] `seo.description` ≤ 160자. 검색 결과에 그대로 노출됩니다.
- [ ] `seo.keywords` 3~6개. 한 글은 하나의 주 키워드에 집중.
- [ ] `seo.canonical` — 다른 곳에도 실린 글이면 원본 URL 지정.
- [ ] `seo.ogImage` — 없으면 `cover.src`가 사용됩니다.
- [ ] 태그 2개 이상 → 내부 링크와 토픽 클러스터 형성.
- [ ] 헤딩 계층이 논리적일 것 (`##` → `###`, 건너뛰지 않기).

`sitemap.xml`, `robots.txt`, `rss.xml`은 자동 생성됩니다. 손으로 관리하지 마세요.

## GEO 체크리스트

- [ ] **`geo.answerSummary`** — 답변 엔진이 통째로 인용할 2~3문장. 이 글의 결론을 먼저 말하세요.
      질문에 대한 직접적인 답으로 시작해야 합니다.
- [ ] **`geo.faq`** — 최소 2쌍. `FAQPage` JSON-LD로 렌더링되고 화면에도 표시됩니다.
      실제로 검색되는 질문 형태로 쓰세요 ("~하는 법", "~와 ~의 차이").
- [ ] **`geo.entities`** — 이 글이 연결되어야 할 고유명사. 제품명, 기술명, 회사명.
- [ ] **`geo.citations`** — 1차 출처. 인용을 다는 페이지가 답변 엔진에 더 자주 인용됩니다.
- [ ] **`geo.locale` / `geo.targetMarkets`** — 지역 타깃팅.

### GEO를 위한 본문 작성법

1. **결론을 먼저.** 답변 엔진은 앞 문단을 우선 추출합니다.
2. **자기 완결적 문단.** 앞 문단을 안 읽어도 이해되는 문단이 인용됩니다. "위에서 말했듯이"를 피하세요.
3. **명시적 수치와 이름.** "빠르다"보다 "빌드가 12초에서 3초로 줄었다".
4. **비교는 표로.** 표는 구조가 명확해 추출 정확도가 높습니다.
5. **질문을 헤딩으로.** `## 왜 파일 기반인가` 같은 헤딩이 Q&A 매칭을 돕습니다.

## 크롤러 정책

`apps/web/app/robots.ts`에서 답변 엔진 크롤러를 **명시적으로 허용**합니다:
`GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`, `OAI-SearchBot`.

인용되려면 먼저 읽혀야 합니다. 이 허용을 막으면 GEO 전략 전체가 무의미해집니다.

## 테크니컬 설정은 따로

메타 태그, 사이트맵 priority, hreflang, robots 지시어, 소유 확인, GA4 는
[08-technical-seo.md](./08-technical-seo.md) 를 보세요. 이 문서는 **무엇을 쓸 것인가**를,
그쪽은 **크롤러에게 어떻게 전달할 것인가**를 다룹니다.

## 검증

```bash
pnpm audit:content   # CLI (admin 검수 화면과 동일한 함수)
pnpm dev:admin       # → http://localhost:3001/seo
```

SEO/GEO 대시보드가 전체 글의 미해결 항목을 lane별로 집계합니다. 개별 글은 검수 화면에서 실제 JSON-LD
출력까지 확인할 수 있습니다.
