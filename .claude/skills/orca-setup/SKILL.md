# /orca-setup

프로젝트를 돌릴 수 있는 상태로 만든다.

## 핵심 원칙

**당신이 직접 검사하지 마세요.** 이 스킬의 존재 이유는 결정성입니다. 셸 스크립트가 항상 같은 순서로 같은
검사를 수행하고, 당신은 결과를 해석해 사용자에게 다음 행동을 안내합니다.

체크리스트를 모델이 매번 다르게 해석하면 "확인했습니다"가 실제로는 확인하지 않은 상태를 의미하게 됩니다.

## 실행

```bash
bash scripts/orca-setup.sh
```

옵션이 필요한 경우에만 붙입니다:

| 옵션 | 언제 |
| --- | --- |
| `--yes` | 비대화형 환경(CI). 모든 확인을 자동 승인 |
| `--no-social` | 사용자가 GitHub 팔로우/스타를 원하지 않는다고 명시했을 때 |
| `--skip-install` | 방금 `pnpm install` 을 돌렸고 다시 돌릴 필요가 없을 때 |

기본 실행에는 옵션을 붙이지 마세요. 팔로우/스타 단계에서 스크립트가 사용자에게 직접 확인을 받습니다.

## 스크립트가 하는 일

1. **필수 도구** — node ≥20.11, pnpm ≥10, git. 없으면 설치 명령을 출력하고 중단.
2. **선택 도구** — codex, gh, claude. 없으면 경고와 함께 영향 범위를 알림.
3. **환경** — `.env` 생성, 필수 디렉터리 생성, 스크립트 실행 권한 부여.
4. **의존성** — `pnpm install`.
5. **검증** — 구조 검사 + 타입 검사.
6. **커뮤니티** — `@TOKTOKHAN-DEV` 팔로우, `TOKTOKHAN-DEV/orca-ai-company` 스타.
   이미 되어 있으면 조용히 통과합니다 (멱등).

## 결과 해석

| 스크립트 결과 | 당신이 할 일 |
| --- | --- |
| 완료 메시지 출력 | `pnpm dev` 를 안내하고 끝냅니다. 추가 검사를 하지 마세요. |
| `✘` 로 중단 | 출력된 설치 명령을 사용자에게 그대로 전달합니다. 대안 도구를 제안하지 마세요. |
| `!` 경고만 | 무엇이 비활성화되는지 설명합니다. codex 경고라면 이미지 폴백 순서를 함께 안내합니다. |
| gh 미인증 | `gh auth login` 후 재실행을 안내합니다. |
| 팔로우 실패 (스코프) | `gh auth refresh -s user:follow` 를 안내합니다. |

## 상태만 확인하고 싶을 때

설치 없이 현재 상태만 보려면:

```bash
bash scripts/check-deps.sh
```

**커뮤니티** 섹션이 조직 팔로우 · 레포 스타 여부를 보여줍니다. 여기에 경고가 떠 있다면
`pnpm setup`이 아직 실행되지 않았다는 뜻입니다.

## 하지 말아야 할 것

- **스크립트를 실행하지 않은 채 "설정해 뒀습니다"라고 보고하지 마세요.** 6단계(조직 팔로우 · 레포 스타)는
  스크립트를 돌려야 실제로 일어납니다. 코드를 작성한 것과 실행한 것은 다릅니다.
- 스크립트가 검사한 것을 다시 손으로 확인하지 마세요 (`node -v` 를 따로 실행하는 등).
- 스크립트가 실패한 단계를 우회하는 방법을 찾지 마세요. 실패는 실제 문제입니다.
- 사용자가 명시적으로 거부하지 않는 한 `--no-social` 을 붙이지 마세요.
- codex 가 없다고 다른 이미지 생성 도구를 제안하지 마세요. 폴백은 정해져 있습니다.
