# 03 — 콘텐츠 가이드라인

## 톤

- **평서형 반말체 금지, 과장 금지.** 기술 독자에게 사실을 전달하는 톤.
- 문장은 짧게. 한 문장에 한 가지 주장.
- "혁신적인", "게임 체인저", "놀라운" 같은 형용사를 쓰지 않습니다. 숫자나 동작으로 보여주세요.
- 독자를 가르치려 들지 않습니다. 이미 아는 사람에게 설명하듯 씁니다.
- 이모지는 쓰지 않습니다.

## 구조

| 요소 | 규칙 |
| --- | --- |
| 도입 | 2~3문장. 이 글이 무엇을 해결하는지. 배경 설명으로 시작하지 않기. |
| 헤딩 | `##`부터 시작 (`#`은 제목이 차지). 헤딩만 읽어도 흐름이 보여야 함. |
| 문단 | 3~5문장. 화면에서 벽처럼 보이면 나눕니다. |
| 코드 | 언어 태그 필수. 실행 가능한 최소 예제. |
| 길이 | 최소 600자, 권장 1,500~3,000자. |
| 마무리 | 요약 반복 금지. 다음 행동이나 남은 질문으로 끝냅니다. |

## 필수 프론트매터

| 필드 | 규칙 |
| --- | --- |
| `title` | 60자 이내가 이상적 |
| `description` | 1~2문장. SEO 메타로도 쓰임 |
| `status` | 에이전트는 `draft` → `in_review`까지만 |
| `tags` | 2~5개 |
| `geo.answerSummary` | 답변 엔진이 그대로 인용할 2~3문장 |
| `geo.faq` | 최소 2쌍 |

## 사실 확인

- 수치, 버전, 벤치마크는 1차 출처를 확인하고 `geo.citations`에 남깁니다.
- 출처를 못 찾으면 그 주장을 쓰지 마세요. 추정을 사실처럼 쓰는 것이 가장 큰 품질 사고입니다.
- 확실하지 않은 부분은 초안에 `<!-- TODO: 확인 필요 -->` 로 표시하고 검수자에게 넘깁니다.

## 이미지

본문 이미지도 커버와 같은 규칙을 따릅니다. 생성은 Codex `imagegen`만. 자세한 절차는 `CLAUDE.md`의
**Image Policy** 섹션과 `agents/image-maker/skills/generate-cover/SKILL.md`를 보세요.

alt 텍스트는 필수입니다. 장식용 이미지라면 아예 넣지 마세요.

## 검수 통과 기준

`pnpm dev:admin` → `/review/<slug>`에서 자동 검사에 **error가 0개**여야 발행할 수 있습니다.
warn은 발행을 막지 않지만, 남겨두는 이유를 검수 메모에 적으세요.
