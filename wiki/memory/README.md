# Memory — 장 · 단기 메모리

세션을 넘어 이어지는 **관찰과 진행 맥락**을 저장합니다. wiki가 "확정된 사실"이라면 memory는 "지금 알고 있는 것"입니다.

```
memory/
├── index.md            ← 장기 메모리 요약. SessionStart 훅이 이 파일을 읽습니다.
├── short-term/         ← 세션 단위 기록. 수명 ~30일.
├── long-term/          ← 승격된 지속 지식. 무기한.
└── _templates/         ← 새 메모리 작성 템플릿
```

## 두 계층

| | 단기 (short-term) | 장기 (long-term) |
| --- | --- | --- |
| 무엇을 | 이번 세션에 무슨 일이 있었나 | 프로젝트에 대해 계속 참인 것 |
| 파일명 | `YYYY-MM-DD-topic.md` | `topic.md` |
| 수명 | ~30일, 이후 정리 대상 | 무기한 |
| 로드 | 최근 5개만 | `index.md` 요약으로 전량 |
| 예 | "admin 폼을 서버 액션으로 전환함" | "사용자는 한국어 응답을 선호한다" |

## 승격 사다리

```
단기 메모리  ──(3회 이상 참조 / 계속 참으로 확인)──▶  장기 메모리
장기 메모리  ──(프로젝트 규칙이 됨)──────────────▶  wiki 문서 or ADR
```

승격은 `/save-memory` 스킬이 판단하고 실행합니다. 손으로 옮겨도 되지만, 그때는 `index.md` 갱신을 잊지 마세요.

## 작성 규칙

1. **한 파일에 한 주제.** 세션 요약을 뭉뚱그리지 말고 주제별로 나눕니다.
2. **상대 날짜 금지.** "어제", "지난주" 대신 `2026-07-27`.
3. **왜를 남깁니다.** 무엇을 했는지보다 왜 그렇게 했는지가 다음 세션에 쓸모 있습니다.
4. **코드에서 알 수 있는 것은 쓰지 않습니다.** 파일 구조나 함수 시그니처는 코드를 읽으면 됩니다.
   메모리에는 코드에 안 남는 것 — 판단 근거, 폐기된 대안, 사용자 선호 — 을 씁니다.
5. **틀린 메모리는 지웁니다.** 오래된 메모리보다 틀린 메모리가 위험합니다.

## 프론트매터

```yaml
---
date: 2026-07-27
type: decision | observation | preference | blocker | progress
topic: admin-server-actions
tags: [admin, forms]
confidence: high | medium | low
promoted: false
---
```

`type` 별 용도:

- `decision` — 무언가를 정했다. 대안과 근거를 함께.
- `observation` — 알게 된 사실. 아직 규칙은 아님.
- `preference` — 사용자/팀의 선호. 장기 승격 1순위.
- `blocker` — 막힌 지점. 해결되면 갱신하거나 삭제.
- `progress` — 진행 상황. 완료되면 삭제 대상.
