# ADR-0003 — SessionStart 훅으로 컨텍스트 자동 로드

- **상태**: 채택됨
- **날짜**: 2026-07-27

## 맥락

이 템플릿이 해결하려는 1번 문제는 **컨텍스트 소실**입니다. 담당자가 바뀌거나, 터미널을 새로 열거나, 며칠 뒤
돌아오면 AI는 프로젝트의 결정 이력을 모릅니다. 결과적으로 이미 폐기한 방식으로 되돌아가거나 같은 논의를
반복합니다.

"필요하면 wiki를 읽어라"라고 지시하는 것만으로는 부족합니다. 모델은 읽어야 할지 판단해야 하고, 종종 읽지
않기로 판단합니다.

## 결정

`.claude/settings.json`의 **SessionStart 훅**이 매 세션 시작 시 `scripts/load-context.sh`를 실행해 다음을
컨텍스트에 주입합니다:

1. `CLAUDE.md`에 정의된 하드 룰 요약
2. `wiki/README.md` 인덱스 (어떤 문서가 있고 언제 읽어야 하는지)
3. `wiki/memory/index.md` — 장기 메모리 요약
4. 최근 단기 메모리 (기본 5개, 30일 이내)
5. git 상태 — 현재 브랜치와 최근 커밋

## 근거

- **판단을 없앤다.** 로드 여부를 모델이 결정하지 않습니다. 항상 로드됩니다.
- **인덱스만 로드한다.** wiki 전문을 넣으면 컨텍스트가 낭비됩니다. 지도를 주고 필요한 문서는 모델이 열게 합니다.
- **메모리는 최근 것만.** 오래된 단기 메모리는 노이즈입니다. 중요한 것은 장기로 승격되어 있어야 합니다.
- **결정적 스크립트.** 셸 스크립트라 모델 버전이나 프롬프트 변화에 영향받지 않습니다.

## 2단 메모리 구조

| 계층 | 위치 | 수명 | 승격 조건 |
| --- | --- | --- | --- |
| 단기 | `wiki/memory/short-term/` | ~30일 | 3회 이상 반복 참조되면 장기로 |
| 장기 | `wiki/memory/long-term/` | 무기한 | 프로젝트 규칙이 되면 wiki 문서로 |

승격은 `/save-memory` 스킬이 관리합니다.

## 트레이드오프

- 매 세션 시작 시 토큰을 소비합니다. 인덱스만 로드해 500~1,500 토큰 수준으로 억제합니다.
- 메모리 파일이 쌓이면 로드 비용이 늘어납니다. `/save-memory`가 정리와 승격을 함께 수행해 억제합니다.
- 훅은 Claude Code 전용입니다. 다른 도구를 쓸 때는 `pnpm context`를 수동으로 실행합니다.
