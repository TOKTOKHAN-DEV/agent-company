# ADR-0002 — 이미지 생성은 Codex imagegen 전용

- **상태**: 채택됨 (하드 룰)
- **날짜**: 2026-07-27

## 맥락

블로그에는 커버 이미지와 본문 삽화가 필요합니다. 생성 경로가 여러 개면 결과물의 품질·스타일·라이선스가
제각각이 되고, 어떤 이미지가 어디서 왔는지 추적할 수 없게 됩니다.

## 결정

**이미지 생성은 Codex CLI의 `imagegen`으로만 합니다.** Claude가 이미지를 합성하는 것은 금지합니다.

Codex를 사용할 수 없을 때의 폴백은 셋 중 하나이며, 이 순서를 따릅니다:

1. **이미지 없이 발행** — 기본값. 이미지는 필수 요소가 아닙니다.
2. **사람이 직접 첨부** — 사용자에게 요청하고 대기합니다.
3. **웹 검색으로 확보** — 라이선스를 확인하고 `cover.license`에 기록합니다.

## 강제 수단

정책을 문서로만 두면 지켜지지 않습니다. 세 겹으로 강제합니다.

1. **스키마** — `ImageSource`는 `codex-imagegen | user-upload | web-search | none`. `claude`라는 값이
   타입 시스템에 존재하지 않으므로 Claude 생성 이미지는 프론트매터에 기록될 수 없습니다.
2. **훅** — `.claude/hooks/guard-image-generation.sh`가 PreToolUse에서 이미지 합성으로 보이는 명령을 차단합니다.
3. **감사** — `auditPost()`가 출처 미기록(`source: none`)과 라이선스 없는 웹 이미지를 error로 처리해
   발행을 막습니다.

## 근거

- **일관성** — 단일 경로에서 나온 이미지는 스타일 프리셋을 공유합니다.
- **추적성** — `cover.origin`에 프롬프트가 남아 재생성이 가능합니다.
- **역할 분리** — Claude는 판단과 글, Codex는 이미지. 각자 잘하는 곳에 둡니다.
- **감사 가능성** — 검수자가 모든 이미지의 출처를 한 화면에서 확인할 수 있습니다.

## 트레이드오프

Codex가 없는 환경에서는 이미지 없는 글이 나옵니다. 받아들입니다 — 출처를 모르는 이미지가 들어가는 것보다
낫습니다.
