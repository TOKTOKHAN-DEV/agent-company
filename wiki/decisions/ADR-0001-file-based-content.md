# ADR-0001 — 콘텐츠 저장소로 마크다운 파일 사용

- **상태**: 채택됨
- **날짜**: 2026-07-27

## 맥락

블로그 콘텐츠를 어디에 저장할 것인가. 후보: (a) Postgres 등 DB, (b) 헤드리스 CMS, (c) 레포 안의 마크다운 파일.

이 템플릿의 1차 사용자는 사람이 아니라 **에이전트**입니다. 에이전트가 콘텐츠를 읽고 쓰는 비용이 선택 기준의
중심입니다.

## 결정

`content/posts/*.md` — 프론트매터를 포함한 마크다운 파일. DB와 외부 CMS를 쓰지 않습니다.

## 근거

- 에이전트에게 파일 읽기/쓰기는 네이티브 동작입니다. DB 접근은 커넥션·마이그레이션·시딩이라는 실패 지점을 만듭니다.
- `git diff`가 그대로 편집 히스토리가 됩니다. 누가 무엇을 왜 바꿨는지 별도 감사 로그가 필요 없습니다.
- 로컬 개발에 인프라가 0입니다. `pnpm install && pnpm dev`로 끝납니다.
- 리뷰가 PR 리뷰와 같은 도구로 이뤄집니다.
- web은 빌드 타임에 전부 정적 생성할 수 있습니다.

## 트레이드오프

- 글이 수천 개로 늘면 전체 스캔이 느려집니다. → 그 시점에 인덱스 캐시를 도입하거나 DB로 마이그레이션합니다.
- 여러 에이전트가 같은 파일을 동시에 쓰면 충돌합니다. → 파이프라인 단계를 순차로 잠가서 회피합니다
  (`wiki/05-agent-operations.md`).
- 비개발자 편집자에게는 admin UI가 필수입니다. → `apps/admin`이 그 역할을 합니다.

## 되돌리려면

`packages/content/src/posts.ts`의 IO 구현만 교체하면 됩니다. 스키마(`schema.ts`)와 소비자(web/admin)는
그대로 둘 수 있도록 파일 IO를 이 모듈 하나에 가둬 두었습니다.
