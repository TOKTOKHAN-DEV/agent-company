# 00 — 프로젝트 개요

## 한 줄 정의

**Agent Company** 는 AI 팀이 굴리는 모노레포 템플릿입니다. 에이전트 IDE 가 준 사무실
(병렬 워크트리, 에이전트마다 하나씩인 터미널, diff 뷰)에 들어갈 **회사**를 담았습니다 —
조직도, 사규, 세션이 끝나도 남는 기억, 사람만 누를 수 있는 출고 버튼.

## 해결하려는 문제

실제 프로젝트를 에이전트에 맡기면 매번 같은 데서 막힙니다. 둘 다 프롬프트를 다듬어서 해결되는
문제가 아닙니다 — 저장소에 없는 것 때문에 생깁니다.

1. **지난 결정이 남지 않는다** — 세션이 끝나거나 다른 에이전트가 이어받으면 지난 석 달의 결정이
   사라진다. 끝난 논쟁을 다시 하고, 이미 버린 방식으로 되돌아간다.
2. **아무도 결과물을 막지 않는다** — 게이트가 없으면 에이전트가 만든 것이 그대로 나간다.
   검수를 모델에게 맡겨도 마찬가지다. 자기 결과물을 채점하면 후하게 준다.

## 해결 방식

무너지는 지점마다 장치를 하나씩 붙였습니다. 문서에 적어 둔 규칙은 지켜지지 않으므로, 누가
기억해서 실행하지 않아도 돌아가는 형태로 만들었습니다.

| 무너지는 것 | 장치 | 강제 수단 |
| --- | --- | --- |
| 컨텍스트 소실 | 핸드북 · wiki 인덱스 · 장단기 메모리 자동 주입 | SessionStart 훅 |
| 품질 드리프트 | 출고 게이트가 결정적 함수 | 게이트에 LLM 호출 없음 |
| 역할 혼재 | 런타임 · 모델 · 쓰기 범위를 선언 | `agents/registry.yaml` |
| 출처 없는 자산 | 이미지 생성 경로 하나 + 출처 기록 | 타입 · 훅 · 감사 3중 |
| 사고 출고 | 에이전트는 `in_review` 까지 | 타입에 경로 없음 |

## 두 층 구조

```
코어      항상 있는 것. 훅 · 메모리 · 레지스트리 · 런처 · 게이트 패턴 · 이미지 정책
템플릿    골라서 펼치는 것. 무엇을 만들고 누구를 뽑는지
```

이렇게 나눈 이유: 컨텍스트 유지와 검수 게이트는 **도메인과 무관하게 필요한 것**이고,
스키마 · 앱 · 에이전트 로스터는 **무엇을 만드느냐에 따라 완전히 달라지는 것**이기 때문입니다.
둘을 한 덩어리로 두면 도메인을 바꿀 때 지우면서 시작해야 합니다.

```
agent-company/
├── .claude/          훅 · 슬래시 커맨드                      ← 코어
├── wiki/             프로젝트 지식 + 메모리 + ADR            ← 코어
├── agents/           로스터                                  ← 코어 (내용물은 템플릿이 채움)
├── scripts/          결정적 셸 스크립트                       ← 코어
└── templates/<id>/   template.yaml + files/                  ← 템플릿
```

자세한 것은 [01-architecture.md](./01-architecture.md).

## 코어 하드 룰

이 규칙들은 코드보다 오래 갑니다. 바꾸려면 [decisions/](./decisions/) 에 ADR 을 먼저 쓰세요.

1. **이미지 생성 경로는 하나다.** 다른 이미지 모델 호출도, SVG 로 대신 그리는 것도 금지.
2. **출고 버튼은 사람이 누른다.** 에이전트는 검수 대기(`in_review`)까지만 올린다.
3. **진실은 저장소 파일이다.** 결과물도 결정도 코드와 같은 저장소에서 버전 관리한다.
4. **게이트는 결정적이다.** 검수에 모델 추론을 넣지 않는다.
5. **컨텍스트는 스스로 올라온다.** 사람이 기억해서 시키지 않는다.

도메인 규칙은 `templates/<id>/template.yaml` 의 `rule:` 에 적고, 세션 시작 시 이 다섯 개 위에
얹혀서 주입됩니다.
