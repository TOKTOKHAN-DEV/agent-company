문제

실제 프로젝트를 맡기면 매번 같은 데서 막힙니다.

모델을 바꾸거나 프롬프트를 다듬어서 해결되는 문제가 아닙니다. 둘 다 저장소에 없는 것 때문에 생깁니다.

지난 결정이 남지 않습니다

세션이 끝나거나 다른 에이전트가 이어받으면 지난 석 달의 결정이 사라집니다. 끝난 논쟁을 다시 하고, 이미 버린 방식으로 되돌아갑니다.

아무도 결과물을 막지 않습니다

게이트가 없으면 에이전트가 만든 것이 그대로 나갑니다. 검수를 모델에게 맡겨도 마찬가지입니다. 자기 결과물을 채점하면 후하게 줍니다.

해법

무너지는 지점마다 장치를 하나씩 붙였습니다.

문서에 적어 둔 규칙은 지켜지지 않습니다. 여기 있는 것들은 누가 기억해서 실행하지 않아도 돌아갑니다.

무너지는 것 장치 강제 수단
context loss 핸드북·위키·장단기 메모리가 세션 시작마다 자동으로 올라옵니다. 전문이 아니라 인덱스만 올려서 컨텍스트를 아낍니다. SessionStart hook
quality drift 출고 게이트는 결정적 함수입니다. 같은 입력이면 사람이 보든 에이전트가 보든 같은 판정이 나옵니다. no LLM in the gate
role bleed 에이전트마다 런타임·모델·쓰기 범위를 레지스트리에 적어 둡니다. 서브에이전트가 아니라 각자의 터미널에서 병렬로 도는 독립 프로세스입니다. registry.yaml
untraceable assets 이미지 생성 경로는 하나뿐이고, 모든 자산에 출처가 기록됩니다. tool guard + audit
accidental shipping 에이전트는 in_review 까지만 올릴 수 있습니다. 출고 버튼은 사람이 누릅니다. humans only

템플릿

어떤 회사를 차릴지 고르세요.

훅·메모리·런처·검수 게이트로 이루어진 코어는 어느 템플릿에서나 같습니다. 템플릿은 이 회사가 무엇을 만들고 누구를 뽑는지만 정합니다. 눌러 보면 위 터미널과 아래 로스터가 바뀝니다.

로스터

직원마다 런타임과 모델, 그리고 벗어날 수 없는 자리가 있습니다.

지금 보고 있는 건 blog 의 로스터입니다. 에이전트는 각자의 터미널에서 도는 독립 프로세스입니다. CLI 도 모델도 다르고 동시에 돕니다. 쓰기 범위는 registry.yaml 에 적혀 있고, 상시 지시는 AGENT.md 에서 옵니다.

에이전트 런타임 모델 쓰기 범위 상시 지시

사규

코드보다 오래 남는 다섯 조항.

세션이 시작될 때마다 모든 에이전트에 주입됩니다. 하나를 바꾸려면 wiki/decisions 에 ADR 을 먼저 써야 합니다. 바꾸기 번거롭게 만들어 둔 것입니다.

이미지 생성 경로는 하나다. 허가된 도구 하나만 쓰고 자산에 출처를 남깁니다. 다른 이미지 모델을 부르거나 SVG 로 대신 그리는 것은 훅이 막습니다.
출고 버튼은 사람이 누른다. 에이전트는 in_review 까지 올리고 멈춥니다. 버튼은 검수 데스크에 있고, 타입에도 그 경로가 없습니다.
진실은 파일에 있다. 결과물도 결정도 코드와 같은 저장소에서 버전 관리됩니다. 데이터베이스를 붙여도 원본은 파일 쪽입니다.
게이트는 결정적이다. 검수 함수에 모델 호출을 넣지 않습니다. 어드민 화면과 CLI 가 같은 함수를 부르므로 사람과 에이전트가 같은 판정을 봅니다.
컨텍스트는 스스로 올라온다. SessionStart 훅이 핸드북·위키 인덱스·메모리를 붙여 줍니다. 누구도 챙겨올 필요가 없습니다.

부팅

빈 폴더에서 돌아가는 회사까지 명령 네 개.

pnpm install 워크스페이스를 받습니다. 필수 조건은 Node 20.11+ 와 pnpm 10+ 둘뿐입니다.
pnpm company-setup 의존성을 전수 검사하고 환경을 준비한 뒤 어떤 템플릿을 펼칠지 묻습니다. 셸 스크립트라 두 번 돌려도 같은 상태를 보고합니다.
pnpm dev 템플릿이 가진 것이 뜹니다. 편집국이라면 공개 사이트와 검수 데스크입니다.
pnpm agent <id> "<task>" 핸드북과 역할, 스킬이 이미 올라간 상태로 에이전트를 자기 터미널에 띄웁니다. 쓰기 범위가 겹치지 않으면 여러 개를 동시에 돌려도 됩니다.
