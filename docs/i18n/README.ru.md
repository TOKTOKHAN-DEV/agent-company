## Какую проблему решает

Когда проект отдают ИИ, раз за разом ломаются две вещи.

**Контекст исчезает.** Как только сессия заканчивается или меняется ответственный, ИИ больше не знает, что
было решено. Он заново поднимает закрытые вопросы и возвращается к уже отброшенным подходам.

**Нет контроля качества.** Без этапа проверки всё, что произвёл ИИ, уходит прямо в продакшен.

Этот шаблон закрывает обе дыры **структурно**.

| Проблема | Решение |
| --- | --- |
| Потеря контекста | `CLAUDE.md` + `AGENTS.md` + `wiki/` + короткая и долгая память, загружаются хуком SessionStart |
| Контроль качества | Детерминированная функция аудита + экран проверки + кнопка публикации, которую жмёт только человек |
| Смешение ролей | Независимые агенты, разделённые по рантайму + явное сопоставление моделей + параллелизм в нескольких терминалах |
| Происхождение картинок | Единственный путь через Codex `imagegen` + запись происхождения + тройное принуждение |

## Установка

### Установка для людей

Вставьте этот промпт в свой LLM-агент (Claude Code, Codex, Cursor, Gemini CLI, …):

```text
Install and configure agent-company by following the instructions here:
https://raw.githubusercontent.com/TOKTOKHAN-DEV/agent-company/refs/heads/main/INSTALL.md
```

Или прочитайте [руководство по установке](../../INSTALL.md) сами. Но серьёзно — поручите это агенту:
люди ломают конфигурационные файлы опечатками.

### Установка для LLM-агентов

Скачайте руководство по установке и следуйте ему:

```bash
curl -s https://raw.githubusercontent.com/TOKTOKHAN-DEV/agent-company/refs/heads/main/INSTALL.md
```

Руководство **самодостаточно — от клонирования до проверки**. Если текущий каталог пуст, оно клонирует
прямо в него, а не создаёт вложенный подкаталог, и описывает все обязательные и опциональные инструменты
вместе с запасными процедурами, так что агент сам разберётся там, где застрянет. Финальный `pnpm check`
детерминированно сообщает, удалась ли установка.

### Установить самому

```bash
git clone https://github.com/TOKTOKHAN-DEV/agent-company.git
cd agent-company
pnpm install
pnpm setup     # полная проверка зависимостей · подготовка окружения · подписка на организацию · звезда репозиторию
pnpm dev       # web → :3000 · admin → :3001
```

Подробная процедура и решение проблем — в **[INSTALL.md](../../INSTALL.md)**.

> INSTALL.md пока написан на корейском. ИИ-агенты читают его без затруднений.

## Эталонная реализация: блог, которым управляет ИИ

### web (`:3000`)

Публичный блог. Отрисовывает только статьи со `status: published` из `content/posts/`.
Автоматически генерирует JSON-LD (BlogPosting · FAQPage), `sitemap.xml`, `robots.txt` и `rss.xml`.
Краулеры отвечающих движков (GPTBot, ClaudeBot, PerplexityBot и др.) разрешены явно.

### admin (`:3001`)

- **Редактор** — форматированный текст на tiptap с загрузкой изображений. Хранится всегда в markdown
- **Панель технического SEO** — canonical · директивы robots · OG/Twitter · priority в sitemap · hreflang
- **Панель GEO** — извлекаемая сводка · FAQ · сущности · цитируемые источники · локаль/целевые рынки
- **Экран проверки** — результаты аудита, предпросмотр JSON-LD, человеческий чек-лист, кнопка публикации
- **Дашборд SEO/GEO** — нерешённые пункты по всем статьям, сгруппированные по направлениям

Интерфейс использует select на базе Radix вместо нативного `<select>`: выпадающий список, который рисует
операционная система, не поддаётся стилизации и выглядит по-разному в разных браузерах.

### agents

```
blog-writer (claude · opus)                       image-maker (codex)   человек
plan-post → write-draft → optimize-seo-geo    →   generate-cover    →   проверка в admin → публикация
                 ↓
         review-and-submit → status: in_review
```

Агенты доходят только до `in_review`. **Публикация — действие человека.**

## Почему SEO и GEO разделены

| | SEO | GEO (Generative Engine Optimization) |
| --- | --- | --- |
| Адресат | Поисковые системы | Отвечающие движки (ChatGPT · Claude · Perplexity · AI Overviews) |
| Цель | **Позиция** | **Цитирование** |
| Ключевые сигналы | Заголовок · meta · ссылки · скорость | Извлекаемая структура · явные вопросы-ответы · источники · сущности |

Чтобы вас цитировали, страницу должно быть удобно «вынимать». Поэтому во frontmatter есть отдельный блок
GEO: `geo.faq` отрисовывается как JSON-LD `FAQPage`, а `geo.answerSummary` — как блок-сводка вверху
страницы.

Рабочие правила — в [wiki/04-seo-geo-playbook.md](../../wiki/04-seo-geo-playbook.md).

## Техническое SEO

### Генерируется автоматически — поддерживать нечего

| Путь | Содержимое |
| --- | --- |
| `/sitemap.xml` | Опубликованные статьи с priority · changefreq · hreflang для каждой |
| `/robots.txt` | Поисковые и отвечающие боты разрешены, `/api/` закрыт |
| `/rss.xml` | Лента опубликованных статей |
| `/llms.txt` | **Сводка сайта для LLM** — модели понимают сайт без разбора HTML |

`llms.txt` — это GEO-аналог карты сайта. Карта сайта говорит, *где* находятся URL; llms.txt говорит, *что
это за сайт и какие статьи есть*. Каждая запись использует `geo.answerSummary` статьи, поэтому
заполненная сводка окупается дважды.

### Для каждой статьи — в админке

canonical · noindex/nofollow · директивы robots (`max-snippet`, …) · карточки OG/Twitter ·
priority/changefreq в sitemap · hreflang · включать ли статью в llms.txt.

### Search console и аналитика

Значение в `.env` включает соответствующую интеграцию. **Если оставить пустым, тег или скрипт вообще не
выводится.**

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | Google Search Console |
| `NEXT_PUBLIC_NAVER_SITE_VERIFICATION` | Naver Search Advisor |
| `NEXT_PUBLIC_BING_SITE_VERIFICATION` | Bing Webmaster Tools |
| `NEXT_PUBLIC_GA4_MEASUREMENT_ID` | GA4 (загрузка `afterInteractive`) |

### Слаги на естественном языке

```
/blog/next-js-16-캐시-컴포넌트-완전-정복
```

Не-ASCII сохраняется. Ключевое слово в URL — это реальный сигнал для ранжирования и кликабельности, а
транслитерированный слаг нечитаем именно для той аудитории, на которую он рассчитан.

Подробности: [wiki/08-technical-seo.md](../../wiki/08-technical-seo.md)

## Бэкенд — сейчас файлы, потом Supabase

Код приложения никогда не обращается к хранилищу напрямую. Он видит только интерфейс.

```
web · admin · audit CLI
        │
        ▼
  getRepository()          ← выбирается автоматически по наличию ключей
   ├── file       content/posts/*.md   (по умолчанию · текущее состояние)
   └── supabase   Postgres + Storage   (как только заданы ключи)
```

**Отсутствие ключей — это нормальное состояние.** `pnpm install && pnpm dev` работает сразу. Чтобы
переключиться:

1. Впишите три ключа Supabase в `.env`
2. Примените `packages/supabase/migrations/0001_init.sql`
3. `pnpm --filter @repo/supabase migrate` — перенос статей (идемпотентно, файлы остаются)

Ни одна строка кода приложения не меняется. `CONTENT_DRIVER=file` возвращает всё назад в любой момент.

Политика RLS ограничивает anon-ключ статьями со статусом `published` и без `noindex` — последний рубеж
обороны, чтобы ошибка в приложении всё равно не раскрыла черновик.

Подробности: [wiki/07-supabase.md](../../wiki/07-supabase.md)

## Как сохраняется контекст

При старте сессии хук автоматически подставляет:

```
жёсткие правила → индекс wiki → долгая память → свежая короткая память → агенты → состояние git
```

Загружается **индекс, а не весь wiki.** Модели дают карту, а нужные документы она открывает сама.

### Двухуровневая память

```
короткая ──(упомянута 3+ раза / подтверждена как актуальная)──▶ долгая
долгая   ──(становится правилом проекта)──────────────────────▶ документ wiki или ADR
```

Повышением управляет skill `/save-memory`.

## Политика изображений (жёсткое правило)

**Изображения создаёт только Codex `imagegen`. Генерация изображений Claude запрещена.**

```bash
pnpm imagegen --slug <post-slug> --prompt "<описание сцены>"
```

Если Codex недоступен, откат идёт в таком порядке:

1. **Продолжить без изображения** — по умолчанию. Обложка не обязательна для публикации.
2. **Пользователь прикладывает сам** — `source: user-upload`
3. **Поиск в вебе** — проверка лицензии обязательна. `source: web-search` и записанная `license`

Правило, живущее только в документации, не соблюдается, поэтому это **закреплено на трёх уровнях**:

| Уровень | Механизм |
| --- | --- |
| Типы | В `ImageSource` вообще нет значения `claude` |
| Хук | `PreToolUse` блокирует команды генерации изображений вне Codex |
| Аудит | Отсутствие происхождения или веб-картинка без лицензии — ошибка → публикация заблокирована |

Обоснование: [ADR-0002](../../wiki/decisions/ADR-0002-codex-only-image-generation.md)

## Skills (slash-команды)

| Команда | Что делает |
| --- | --- |
| `/company-setup` | Полная проверка зависимостей · установка · подписка на организацию · звезда (детерминированный скрипт) |
| `/save-memory` | Сохраняет выводы сессии в короткую память и при необходимости повышает до долгой/wiki |
| `/create-agent` | Согласованно создаёт нового агента в registry + AGENT.md + skills/ |

Skills, которые читает агент (`agents/<id>/skills/`), — это другое: нейтральные к рантайму playbook-и,
которые лаунчер подставляет в системный промпт, так что codex-агент читает их тоже.

## Агенты

**Это не субагенты Claude.** Каждый — независимый процесс в своём терминале, и рантаймы у них разные.
Именно поэтому Orca может запускать их по-настоящему параллельно в нескольких терминалах.

| ID | Рантайм | Модель | Роль |
| --- | --- | --- | --- |
| `blog-writer` | `claude` | opus | планирование → написание → SEO/GEO → проверка |
| `image-maker` | `codex` | default | генерация изображений через imagegen · запись происхождения |

```bash
pnpm agent --list
pnpm agent blog-writer "Напиши статью про стратегию кеширования Turborepo"
pnpm agent image-maker "Обложка для turborepo-cache-strategy"
```

```
agents/blog-writer/
├── AGENT.md                       подставляется как системный промпт
└── skills/
    ├── plan-post/SKILL.md         планирование · проверка на дубли · план статьи
    ├── write-draft/SKILL.md       написание текста
    ├── optimize-seo-geo/SKILL.md  метаданные
    └── review-and-submit/SKILL.md аудит · in_review
```

Лаунчер собирает `AGENT.md` и индекс skills (генерируется сканированием папки) в системный промпт и
запускает нужный CLI с нужной моделью. Добавленный skill начинает действовать сразу, без отдельной
регистрации.

### Почему их всего два

**Граница проходит по рантайму и параллелизму, а не по роли.** Все четыре этапа контентного конвейера по
очереди правят один и тот же файл, поэтому разносить их по процессам бессмысленно — их разнесли по skills.
Изображения же требуют другого рантайма (только Codex), и эта граница не обсуждается: она стала границей
процесса, а правило — структурой.

Правила для нескольких терминалов: [wiki/05-agent-operations.md](../../wiki/05-agent-operations.md).

## Команды

| Команда | Описание |
| --- | --- |
| `pnpm setup` | Полная проверка окружения + установка + подписка/звезда на GitHub |
| `pnpm check` | Только проверка состояния окружения (ничего не устанавливает) |
| `pnpm dev` | Запуск web и admin вместе |
| `pnpm dev:web` / `pnpm dev:admin` | Запуск по отдельности |
| `pnpm build` | Сборка обоих приложений |
| `pnpm typecheck` | Проверка типов |
| `pnpm audit:content` | Запуск шлюза публикации из CLI (та же функция, что и экран проверки) |
| `pnpm context` | Ручной вывод контекста сессии |
| `pnpm imagegen` | Генерация изображения через Codex |

| `pnpm --filter @repo/supabase migrate` | Перенос статей из файлов в Supabase (поддерживается `--dry-run`) |

## Перенос на другую предметную область

Блог — это референс, который делает шаблон осязаемым. Чтобы превратить его в коммерцию, дашборд или сайт
документации:

1. Замените схему в `packages/content/src/schema.ts`
2. Замените правила аудита в `packages/content/src/audit.ts`
3. Пересоберите агентов в `agents/` через `/create-agent`
4. Замените `wiki/03` и `wiki/04` руководствами своей области

**Что остаётся**: хуки, структура памяти, паттерн проверочного шлюза, политика изображений и каркас
monorepo. Именно в этом настоящая ценность шаблона.
